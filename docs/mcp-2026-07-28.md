# MCP protocolVersion 2026-07-28

This implementation supports only the stateless MCP Streamable HTTP revision
`2026-07-28`. Earlier protocol revisions and their session-based lifecycle are
not supported.

For the 2026-07-28 path, every POST must include all of the following:

- `MCP-Protocol-Version: 2026-07-28`
- `Mcp-Method`, equal to the JSON-RPC `method`
- `Mcp-Name` for `tools/call` and `resources/read`, equal to `params.name` or
  `params.uri`
- `params._meta.io.modelcontextprotocol/protocolVersion`
- `params._meta.io.modelcontextprotocol/clientCapabilities`

The protocol version in the HTTP header and request `_meta` must be identical.
The server returns JSON-RPC error `-32020` for mismatched request headers and
`-32022` for an unsupported protocol version.

`initialize`, `notifications/initialized`, HTTP GET/DELETE, and the
`Mcp-Session-Id` header are not supported. An APEX session is created only for
the duration of each request and is never sent to the client. Where RAS is
configured, the RAS session has the same request lifetime.

## Browser origins

Requests without an `Origin` header are accepted for native MCP clients. If a
request has an `Origin` header, its exact serialized origin must be present in
`OJ_MCP_ALLOWED_ORIGINS`; otherwise the server returns HTTP 403. The table is
empty after installation, so browser access is denied by default. For example,
allow a locally hosted client with:

```sql
insert into oj_mcp_allowed_origins(origin)
values ('http://127.0.0.1:8181');
commit;
```

Store only trusted origins and include the non-default port when applicable.

Use `server/discover` to obtain the server capability set and supported
versions:

```http
POST /ords/<schema>/<module>/mcp HTTP/1.1
Content-Type: application/json
MCP-Protocol-Version: 2026-07-28
Mcp-Method: server/discover

{"jsonrpc":"2.0","id":1,"method":"server/discover","params":{"_meta":{"io.modelcontextprotocol/protocolVersion":"2026-07-28","io.modelcontextprotocol/clientCapabilities":{}}}}
```

Successful results include `resultType: "complete"` and server identity in
`_meta.io.modelcontextprotocol/serverInfo`. Discovery and the list/read
methods include the required `ttlMs` and `cacheScope` cache metadata. The
server does not advertise change notifications because it does not implement
the `subscriptions/listen` stream.
